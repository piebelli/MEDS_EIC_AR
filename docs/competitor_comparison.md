# MEDS-EIC-AR vs. competing autoregressive EHR models

**Purpose.** This document is the "competitor table" agreed on in the MEDS-EIC-AR planning call. It
lists the autoregressive (AR), generative EHR models that a reader would naturally reach for instead
of MEDS-EIC-AR, records whether each has public code, and spells out the architectural, tokenization,
filtering and inference differences between each one and MEDS-EIC-AR as it exists on `main` today.
For each competitor it ends with a concrete recipe for what would have to change in MEDS-EIC-AR to
turn it into a faithful clone, so that clones can be built as *configuration variants of one codebase*
rather than as separate re-implementations.

**Framing (from the call).** The paper's claim is narrow on purpose: MEDS-EIC-AR is a dataset-agnostic,
easy-to-run, efficient AR model that performs *at parity with or better than* the AR models people
would otherwise use. Nothing here is a novelty claim. Non-AR models (EveryQuery, MOTOR, BERT-style
encoders) and supervised baselines (XGBoost, logistic regression) are deliberately out of scope; see
§6. Dates in this document are as of 2026-11-06.

**How to read the tables.** "MEDS-EIC-AR today" cells are taken from the code on `main` (file pointers
given). Competitor cells are taken from the cited paper or repository; where a paper does not state
something, the cell says so rather than guessing.

## 1. MEDS-EIC-AR as it stands today (the reference column)

| Numeric values              | Quantile-binned into 10 equal-frequency bins per code (9 quantiles), then **fused with the code into a single token**, e.g. `HR//value_[102.6,105.1)`; raw value dropped                                                                                                                                                             | `_data.yaml` (`fit_quantile_binning`, `bin_numeric_values`)                        |
| Text values                 | Dropped (MEDS `text_value` is not tokenized)                                                                                                                                                                                                                                                                                         | —                                                                                  |

| Absolute time features      | `AGE` (quantile-binned, 10 bins) and `TIME_OF_DAY//[hh,hh)` (4 bins: 00-06, 06-12, 12-18, 18-24) tokens at **every unique event time**                                                                                                                                                                                               | `_data.yaml` `add_time_derived_measurements`                                       |
| Sentinels                   | `TIMELINE//START` at the first event, `TIMELINE//END` after the last (EOS for generation)                                                                                                                                                                                                                                            | `_data.yaml`, `generation/utils.py`                                                |
| Tokens per event (overhead) | +3 structural tokens per distinct timestamp (DELTA, AGE, TIME_OF_DAY) plus 1 token per measurement                                                                                                                                                                                                                                   | derived                                                                            |
| Within-event order          | Derived tokens first (TIMELINE//START, AGE, TIME_OF_DAY, DELTA), then the event's measurements in MEDS row order; no learned/canonical ordering                                                                                                                                                                                      | MEDS-transforms stage sort (subject, time, stable)                                 |
| Vocabulary filtering        | Drop timed codes seen in fewer than `MIN_SUBJECTS_PER_CODE` subjects (**default 1000**; demo 2). | Subject filtering           | Drop subjects with fewer than `MIN_EVENTS_PER_SUBJECT` events (**default 10**)                                                                                                                                                                                                                                                       | `_data.yaml` `filter_subjects`                                                     |

| Backbone                    | HF `LlamaForCausalLM`: pre-RMSNorm, SwiGLU (intermediate = 4 x hidden), full-dim RoPE, no biases, MHA by default (GQA opt-in via `num_key_value_heads`), FlashAttention-2 when installed                                                                                                                                             | `model/model.py`                                                                   |
| Sizes shipped               | micro 4L/4H/256d (~4M non-emb.), small 8L/8H/512d (~34M), medium 12L/12H/768d (~113M), large 24L/16H/1024d (~400M); vocab-dependent embeddings on top. EveryQuery (2026) reports its MEDS-EIC-AR baseline at 102M params                                                                                                             | `configs/lightning_module/model/*.yaml`                                            |
| Context length              | `max_seq_len` default **512** (EveryQuery baseline used 1024)                                                                                                                                                                                                                                                                        | `configs/_pretrain.yaml`                                                           |
| Training                    | Next-token cross-entropy over all tokens; AdamW (lr 5e-4, wd 0.01), cosine schedule with 10 % warm-up, 50k steps default, grad-clip 1.0, 16-mixed; `BALANCED_RANDOM` subsequence sampling per subject per epoch                                                                                                                      | `configs/trainer/default.yaml`, `optimizer/adamw.yaml`, `datamodule/pretrain.yaml` |
| Validation metrics          | Next-code top-k accuracy and perplexity                                                                                                                                                                                                                                                                                              | `training/metrics.py`                                                              |
| Generation                  | Ancestral sampling at temperature 1, **no top-k/top-p truncation** (deliberate: truncation biases Monte Carlo probabilities, issue #159); greedy optional; stops at `TIMELINE//END` or token budget; rolling sliding-window generation beyond the per-chunk context; input/generation split defaults to 25 % / 75 % of `max_seq_len` | `configs/inference/default.yaml`, `model/model.py`, `backends/sglang.py`           |
| Trajectories per sample     | Default **20**, interleaved into one predict pass; subsample-able post hoc for N-vs-AUC curves                                                                                                                                                                                                                                       | `configs/inference/default.yaml`, `generation/repeated_dataset.py`                 |
| Inference engines           | HF `generate` (default) or **SGLang** engine (checkpoint exported to HF format; FlashInfer/Triton attention, CUDA graphs, continuous batching)                                                                                                                                                                                       | `model/backends/`                                                                  |
| Prediction resolution       | Trajectories written in `MEDS_trajectory_evaluation` schema; labels resolved by applying (zero-shot-converted) ACES task configs to generated futures; per trajectory `valid` / `determinable` / `label`; probability = fraction of determinable trajectories positive                                                               | `generation/finalize.py`, MEDS_trajectory_evaluation                               |
| Variance-reduced estimators | Not yet integrated (SCOPE / REACH, arXiv 2602.03730, are the planned addition)                                                                                                                                                                                                                                                       | —                                                                                  |
| Datasets used so far        | MIMIC-IV, NWICU, a private AMC (EveryQuery baseline); scaling-law runs in progress in the lab                                                                                                                                                                                                                                        | external                                                                           |
| Code / license              | https://github.com/mmcdermott/MEDS_EIC_AR, MIT, on PyPI, CI + tests                                                                                                                                                                                                                                                                  | —                                                                                  |

## 4. Per-competitor differences and clone recipes

Effort scale: **Config** = YAML/CLI change only; **Stage** = new or modified MEDS-transforms stage
(pre-processing only, model untouched); **Model** = change to the network or loss; **Infra** =
inference/formatting code.

### 4.1 ETHOS and ETHOS-ARES (Tier 1, highest priority)

Why it matters: the most-cited open AR zero-shot model, already MEDS-based (ARES), already used by
the lab (EveryQuery §6.3 compared against it; SCOPE/REACH used ETHOS-ARES). Reviewers will ask for
it first.

| Dimension                   | ETHOS / ARES                                                                                         | MEDS-EIC-AR today                            | Why it could matter                                                                                                                                                                 | Change to clone                                                                                                                                                                            | Effort                        |

| Vocabulary scope            | Hand-picked tables; top-200 labs; everything else dropped                                            | Everything above the subject-count threshold | ETHOS's task is easier (less to model) but it cannot answer questions about dropped codes                                                                                           | Add a code allow-list stage (regex on MEDS code prefixes) mirroring ETHOS's table set and a top-k-labs filter                                                                              | Stage                         |

### 4.2 Curiosity / CoMET (Tier 1)

Why it matters: the largest-scale AR EHR model and the paper with scaling laws; no code, no data, so
parity can only be shown with a clone-by-description on public data.

### 4.7 Event Stream GPT (Tier 2, lineage)

ESGPT is the direct predecessor of this line of work (same group). It models each *event* as one
position with multiple measurements, a user-specified intra-event dependency graph realised by nested
attention, a parametric time-to-event head and continuous regression heads for numeric values.
Nothing in that design can be reproduced as a tokenization variant of MEDS-EIC-AR; it is a different
architecture. Recommendation: cite as lineage and as the "one position per event" alternative, do not
clone. If a reviewer insists on an ESGPT number, the original repo still runs on MIMIC-IV.

### 4.8 Tier 3 (cite, do not clone)

- **EHRMamba**: Mamba backbone, visit wrappers, week-granularity interval tokens, Time2Vec age/time
    embeddings, 5-bin lab values, 2048 context; evaluated by fine-tuning, with forecasting only as a case
    study. Cite in the architecture ablation discussion.
- **UCLA JAMIA GPT**: CEHR-GPT-like with quarter-granularity time tokens (4 bins), lab deciles, greedy
    next-visit generation; no code. Cite as evidence of the time-token-granularity axis.
- **RAVEN / next-visit models (NYU)**: next-visit *multi-label* objective, not token-level AR; the
    2026 paper claims to outperform "simulation-based next-token approaches" in zero-shot incidence
    forecasting. Worth citing as the main objective-level critique of the AR Monte Carlo approach.
- **HALO**: hierarchical visit/code generator for synthetic MIMIC-III; a synthetic-data model, not a
    zero-shot predictor.
- **Federated generative event models (Burkhart et al., 2026)**: tokenized generative event models on
    three CLIF-format ICU systems with FedAvg; relevant to the multi-dataset story, not to tokenization.
- **NEP (Chen et al., 2025)**: LoRA-tuned text LLMs over serialized events; a different modality.

## 5. Tokenization and inference axes that fall out of the table

These are the knobs that distinguish the competitors from MEDS-EIC-AR and that a clone grid would
need. Each is implementable as a MEDS-transforms stage option or a Hydra override, which is what
makes "clone = config variant" viable.

| Axis                    | Values seen in the literature                                      | MEDS-EIC-AR default   | Needed for clones of                         |
| ----------------------- | ------------------------------------------------------------------ | --------------------- | -------------------------------------------- |
| Code hierarchy          | flat; ICD/ATC prefix multi-token                                   | flat                  | ETHOS, Curiosity                             |
| Value encoding          | fused code+bin; separate Q-token; 5 bins; none; continuous         | fused, 10 bins        | ETHOS, Curiosity, EHRMamba, CEHR-GPT, Delphi |
| Inter-event time        | 13/19/22 log bins; day-integer tokens; none; continuous + TTE head | 22 bins               | all                                          |
| Minimum-gap suppression | none; < 5 min omitted                                              | none                  | ETHOS, Curiosity                             |
| Long-gap encoding       | single wide bin; repeated 6-month tokens; LT token                 | single wide bin       | ETHOS, Curiosity, CEHR-GPT                   |
| Per-event absolute time | none; age/TOD per event; age once                                  | AGE + TOD per event   | Context Clues, CEHR-GPT, ETHOS               |
| Static demographics     | omitted; prefix tokens                                             | omitted               | ETHOS, Curiosity, CEHR-GPT, Delphi           |
| Visit structure         | none; VS/VT/VE wrappers; encounter headers                         | none                  | CEHR-GPT, Curiosity                          |
| Modality allow-list     | everything; curated tables; dx-only                                | everything            | all Tier 1, Delphi                           |
| Vocab cap               | subject-count threshold; top-k codes; top-k labs                   | >= 1000 subjects      | ETHOS, Curiosity, Context Clues              |
| Occurrence policy       | all; first occurrence only                                         | all                   | Delphi                                       |
| Context length          | 512 - 8192                                                         | 512                   | Curiosity, Context Clues                     |
| Backbone                | GPT-2, Llama, Qwen2, Mamba, Hyena                                  | Llama                 | ablation                                     |
| Decoding                | ancestral; top-p 0.9; top-k 100; greedy                            | ancestral             | ETHOS-ARES, Foresight                        |
| Trajectories            | 20, 50, 100 (+ SCOPE/REACH)                                        | 20                    | all                                          |
| Censoring rule          | determinable-fraction; right-censored ratio; discard-and-resample  | determinable-fraction | Curiosity, CEHR-XGPT                         |
| Stop rule               | EOS/budget; task-specific tokens; horizon reached                  | EOS/budget            | ETHOS, Curiosity                             |

Two gaps in MEDS-EIC-AR's defaults stand out as likely to cost performance rather than just differ:
the omitted static demographics, and the +3 structural tokens per timestamp (which shortens the
effective context at 512 tokens). Both are config-level fixes and should be the first ablations.

## 6. Deliberately excluded (and why)

- **EveryQuery** (arXiv 2603.07900): non-AR, task-conditioned; already compared against MEDS-EIC-AR in
    its own paper. Including it would turn the paper into an "AR vs. non-AR" claim.
- **MOTOR, CLMBR (original), CEHR-BERT, BEHRT/Med-BERT, Hi-BEHRT, TransformEHR**: time-to-event or
    encoder-style pre-training; not generative zero-shot models.
- **MEDS-Tab / XGBoost / logistic regression**: supervised baselines are a different contribution
    (lab benchmarking effort); per the call, including them would mislead reviewers about the AR claim.
- **Text LLM approaches** (NEP, EHR-R1 and similar): different modality.

## 7. Evaluation substrate (for the experimental grid)

- **Random tasks as the ranking proxy**: Pollet & McDermott, "Rethinking How We Evaluate Methodological
    Progress in Health AI" (arXiv 2609.18134, Sep 2026). Randomly sampled (code, horizon) tasks on
    MIMIC-IV and NWICU rank algorithms consistently with expert-authored clinical tasks. Plan: reuse the
    same task set, scored zero-shot.
- **EveryQuery's AR baseline setup** (useful as a starting grid): MEDS-EIC-AR 102M, `max_seq_len` 1024
    with 256 tokens of context, K = 20 trajectories, 100 random codes x 8 horizons per dataset, on
    MIMIC-IV (vocab 11,476), NWICU (vocab 2,159) and a private AMC.
- **Variance reduction**: SCOPE and REACH (Solo, McDermott et al., arXiv 2602.03730) match 100-sample
    Monte Carlo with ~10 samples on ETHOS-ARES; to be integrated as an estimator option.
- **Datasets available in MEDS**: MIMIC-IV, NWICU, eICU (MEDS-DEV), plus other PhysioNet sets.

## 8. Suggested order of work

1. **Default fixes / ablations** (Config): static prefix on; AGE/TOD tokens off; context 1024-2048.
2. **ETHOS clone** (Stage + Infra): hierarchical code expansion, separate value tokens, ETHOS interval
    bins with < 5-minute suppression, table allow-list; validate against a direct ETHOS-ARES run on the
    same MEDS extract.
3. **Curiosity-style configuration** (Config on top of 2): Qwen2/GQA backbone, 8192 context, top-1000
    labs / top-1500 procedures caps, compute-optimal size from the lab's iso-FLOP curves.
4. **CEHR-GPT clone** (Stage): visit wrappers, day-integer deltas across visits only, dx/med/proc only.
5. **Context Clues / Foresight tokenizations** (Config): no-time and codes-only variants.
6. **Delphi-2M approximate clone** (Stage): diagnoses-only, first occurrence, no-event tokens.
7. Inference-efficiency Pareto study across HF vs SGLang, N trajectories, SCOPE/REACH, and
    task-aware stopping, on reference hardware.
