# MEDS-EIC-AR vs. other autoregressive EHR models

**Status:** draft for discussion, 2026-11-20. **Owner:** Pietro. **Reviewer:** Matthew.

This is the competitor table from our call. It lists the autoregressive (AR) EHR models we would want to
show parity with and compares each one with MEDS-EIC-AR on every design choice that could change
performance or that a copy would have to reproduce. Section 3 is the table. Everything compared in this
document is a row of that table.

Scope follows the call: AR generative models only. EveryQuery, supervised baselines and encoder-style
models are left out on purpose (section 5).

## 1. Where the information comes from

Each cell is read from the model's **source code** at the commit named in the row "Code read for this
table". The exceptions are marked in the table:

- A cell ending in *(paper)* is stated in the paper and was not found or not checked in the code.
- Curiosity has no public code, so its whole column is from the paper.
- "n/s" means neither the code nor the paper states it. "—" means the criterion does not apply.

numbers without any change to the tokenization.

## 4. What reading the code changed

These are places where the source code differs from the paper, or from the earlier draft of this table.

- **ETHOS-ARES sampling.** The paper describes nucleus sampling with p = 0.9. The released inference code
    samples at temperature 1 with no truncation. A copy has to pick one; I would follow the code.
- **ETHOS-ARES inference cost.** The generation loop has no key-value cache and re-runs the full context
    for every new token. This is the concrete basis for the efficiency comparison against SGLang.
- **ETHOS-ARES has no calendar-year token.** The 2024 model had one. ARES keeps sex, race, marital
    status, BMI and age only.
- **ETHOS age is recomputed per window.** The static tokens are rebuilt for the start time of each
    context window, so they are always visible and always current.
- **ETHOS training windows cross patient boundaries.** Windows are cut from one concatenated token
    stream. MEDS-EIC-AR keeps one subject per sequence.
- **The CEHR-GPT repository has moved past its papers.** It now has a Qwen2 backbone option, an optional
    value-token path, a MOTOR-style loss and a smoke test for "CoMET-tokenized" data. That group appears
    to be building its own Curiosity-style variant.
- **Foresight does encode time.** It puts a separator token between day buckets and inserts an age token
    whenever the age in years changes. The earlier draft said it had no time tokens.
- **Delphi-2M context is 96 tokens**, not the 1,024 default in its model file.
- **Context Clues has no generation code.** Its Llama config uses grouped-query attention (4 key-value
    heads), which the paper does not highlight.
- **MEDS-EIC-AR upstream has a stale branch with tokenization switches.**
    `codex/add-control-switches-for-preprocessing-options` (July 2025, unmerged, far behind `main`) added
    environment switches for the number of value quantiles, custom bin files, dropping numeric values
    and data-driven time bins. These are some of the options the copies need.

Two 2026 tokenization papers bear directly on rows of the table and should be cited. Guo et al.
(arXiv 2603.15644) report that fusing code and attribute into one token beats separate tokens on 73 of
74 tasks, which supports MEDS-EIC-AR's value encoding against the ETHOS choice. Thukral et al.
(arXiv 2606.15447) report that encoding ICD hierarchy beats flat codes in a BERT-style model, which cuts
the other way.
