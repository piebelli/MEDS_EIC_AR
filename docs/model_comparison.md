# MEDS_EIC_AR vs. other autoregressive EHR models

Working draft, November 2026. Owner: Pietro Belligoli. Purpose: the competitor list and difference table
agreed with Matthew McDermott as the first deliverable for the MEDS_EIC_AR tool paper.

## 1. Scope

The paper makes one claim: **MEDS_EIC_AR is a reliable, usable stand-in for state-of-the-art autoregressive
(AR) pre-training on EHR data, and it runs on any MEDS dataset.** To support that claim, MEDS_EIC_AR needs to
perform about as well as, or better than, the AR models a reader would naturally reach for, and to be about
as efficient or more so. This document therefore:

1. Lists those competitors, with code availability.
2. Describes how each one differs from the current MEDS_EIC_AR, in architecture, tokenization, data
    filtering and zero-shot inference.
3. Says how to modify MEDS_EIC_AR so that it reproduces each competitor ("clone it";
    [Section 6.1](#61-clone-recipes-how-to-turn-meds_eic_ar-into-each-competitor)). Comparisons then run on
    one code path, and any competitor choice that turns out better can simply be adopted by MEDS_EIC_AR.

Out of scope by agreement (see [Section 8](#8-out-of-scope-and-why)): EveryQuery, supervised baselines
(XGBoost, logistic regression, MEDS-Tab), and non-autoregressive models. Efficiency is characterized
through ablations (HF vs. SGLang, Monte Carlo vs. SCOPE/REACH). It is not claimed as a novel contribution.

## 2. TL;DR

- **Must show parity with:** ETHOS / ETHOS-ARES (public code, MEDS input, MIMIC-IV only) and CoMET /
    "Curiosity" (Epic, no code, recipe described in detail). The lab's benchmarking effort is already cloning
    both. **Strongly recommended:** CEHR-GPT / CEHR-XGPT, which has public code, reads MEDS, and does
    zero-shot inference by generation. **Secondary:** Delphi-2M, ESGPT, and the Microsoft scaling-law
    paper (ETHOS tokens on a Llama backbone).
- **Claim risk.** CEHR-GPT's README now advertises MEDS support. In practice it needs a per-dataset Python
    class to rebuild visits; only MIMIC-IV and OMOP rules ship with it. ETHOS-ARES reads MEDS, but its
    tokenizer hard-codes MIMIC-IV tables and code maps. The defensible claim is therefore *"the only public
    AR codebase that consumes an arbitrary MEDS dataset with no dataset-specific rules or code maps,"* not
    *"the only MEDS-compatible one."*
- **Biggest conceptual differences.** Every priority-A and -B competitor conditions on demographics and
    age; MEDS_EIC_AR currently gives the model neither (static codes are omitted at load and there is no age
    token). ETHOS, CoMET and CEHR-XGPT also use much longer histories (2k to 8k tokens, versus a 512-token
    model with 128 tokens of prompt by default). ETHOS and CoMET shrink the vocabulary through ontology decomposition and hand-picked
    data types. MEDS_EIC_AR instead keeps every data type but deletes every code seen in fewer than 1,000
    subjects. [Section 7](#7-things-in-meds_eic_ar-worth-discussing-before-the-comparison) argues that the
    first two should probably be fixed in MEDS_EIC_AR itself before any comparison is run.
- **Choices where MEDS_EIC_AR already looks best in class:** joint code×value tokens (supported by a 2026
    MEDS ablation, 73 of 74 tasks), unbiased ancestral sampling (ETHOS-ARES reports top-p 0.9, which biases
    Monte Carlo risk estimates), KV-cached HF or SGLang inference (ETHOS-ARES recomputes the full sequence
    for every token), and per-patient window sampling (supported by a 2026 sampling study).

**Key contrast.** MEDS_EIC_AR and ETHOS/CoMET sit at opposite ends. MEDS_EIC_AR keeps every data type but

hierarchical split could be done generically, without dataset-specific maps (see
[Section 6](#6-ablation-axes-the-knobs-these-comparisons-turn-into)).

## 6. Ablation axes (the knobs these comparisons turn into)

Each competitor is a point in this space. Effort: **cfg** = a Hydra or env override in this repo;
**stage** = a new or extended MEDS-transforms stage; **mtd** = a meds-torch-data option or hook; **model** =
a change to `Model` or `MEICARModule`; **map** = needs dataset-specific mapping files, which conflicts with the
"any MEDS dataset" claim unless it can be driven from MEDS `parent_codes` metadata.

## 7. Things in MEDS_EIC_AR worth discussing before the comparison

These came out of the table. Items 1–5 are places where MEDS_EIC_AR differs from all of the priority-A
competitors, in a way that probably hurts it, so the answer may be "MEDS_EIC_AR changes its default." That fits the framing of
always matching the best choice.

1. **No demographics.** `static_inclusion_mode: OMIT` (`configs/datamodule/default.yaml:8`) means sex, race
    and other static codes never reach the model, even though preprocessing keeps them (`_data.yaml:21-23`
    exempts them from filtering). Every competitor conditions on at least sex and age.
2. **No age or calendar time.** `age: null`. With 512-token `BALANCED_RANDOM` windows, `MEDS_BIRTH` and the
    birth-to-first-event delta are usually outside the window, so most training windows carry no age
    information. CoMET goes further and encodes calendar time, which matters for practice drift.
3. **Very short zero-shot history.** By default the prompt is 25% of 512, or 128 tokens, and a delta token
    sits between every distinct timestamp. In ICU data that may cover only a few hours. ETHOS uses up to
    2,048 tokens of history and CoMET up to 8,192. This is probably the largest single driver of any gap,
    and it belongs in the grid as a context-length sweep.
4. **Rare-code deletion at 1,000 subjects.** On MIMIC-IV (~300k patients) this removes every code seen in
    fewer than ~0.3% of patients, along with all its values. This deserves a "measurements retained" number
    next to ETHOS's and CoMET's to make the capability trade-off explicit.
5. **Delta tokens under one minute.** These cost tokens and carry little signal. ETHOS's 5-minute floor is
    a cheap, defensible change (knob 6).
6. **Already best in class, so emphasize these:** joint tokens (knob 4), unbiased sampling (knob 17),
    KV-cache and SGLang inference (knob 20), per-patient window sampling (knob 12), and generic MEDS input
    with generic trajectory readout.

## 9. Proposed next steps

1. **Agree on the competitor list:** A = ETHOS-ARES and CoMET/Curiosity; A− = CEHR-GPT; B = Delphi-2M,
    ESGPT, and the Zhang et al. scaling paper. Check against the lab's benchmarking clone list to avoid
    duplicated effort.
2. **Decide on defaults first** (Section 7, items 1–3 and 5): rerun the baseline with static codes prepended, an
    age prefix, a longer context and a 5-minute delta floor. If it improves, it becomes the new default.
3. **Express each clone as a config bundle** (e.g. `preprocessing/configs/_ethos_like.yaml` plus a
    `lightning_module/ethos_like.yaml`). Only knobs 4, 6, 9, 11, 15 and 19 need new code. Each clone can then
    run through the lab's shared inference interface once it exists.
4. **Experimental grid seed:** datasets MIMIC-IV, NWICU and eICU, then more PhysioNet sets. Tasks: the same
    random tasks as the random-task ranking paper (likely [arXiv 2609.18134](https://arxiv.org/abs/2609.18134);
    confirm with Matthew), plus the ETHOS-ARES clinical tasks on MIMIC-IV, for an apples-to-apples number
    against the published results. Metrics: AUROC/AUPRC, N-trajectory curves (generate about 100 and
    subsample), GPU-seconds per 1k trajectories, tokens per patient-day, and % of raw measurements retained.
5. **Run the original codebases where possible** (ETHOS-ARES on MEDS MIMIC-IV; CEHR-GPT through its MEDS
    path) so that the clones can be validated against the real implementations.

## 10. Caveats

- Figures for competitors come from their papers and READMEs, and from reading the ETHOS-ARES, CEHR-GPT and
    Delphi source where noted. Where a paper contradicts itself, the table says so. Examples: ETHOS-ARES
    reports top-p 0.9 while its code samples untruncated; Context Clues describes its vocabulary selection
    two different ways.
- Foresight, EHRMamba and ESGPT internals are summarized at a higher level and should be re-checked before
    they go into a paper table.
- Competitor parameter counts are as reported. MEDS_EIC_AR counts are 16·L·d², excluding embeddings.
